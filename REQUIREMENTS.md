# Требования к проекту: Telegram-бот для агрегации новостей

## 1. Основная идея

Сократить время на чтение и поиск новостей. Бот опрашивает пользователя о новостных темах, которые нужно отслеживать, а также о глубине и детализации по каждой теме, получает от пользователя ссылки на источники и/или отслеживает общедоступные источники. Агрегирует новости по темам и публикует их пользователю в Telegram с настроенной периодичностью.

## 2. User stories

Как пользователь, я хочу:

1. Задать список тем и источников, чтобы бот знал, что искать.
2. Чтобы бот использовал заданные мной источники или общедоступные источники по темам — в зависимости от того, что я укажу.
3. Чтобы бот учитывал глубину и детализацию по каждой теме. Например:
   - если я хочу детально следить за новостями об изменении налогообложения — в дайджесте должны фигурировать выдержки из закона, пояснения, ссылки на первоисточники;
   - если тема мне интересна поверхностно (например, новости о BTS) — достаточно ключевой информации одной строкой.
4. Чтобы бот использовал ИИ для поиска, анализа и агрегации новостей.
5. Получать дайджест новостей N раз в день, в заданное время — в зависимости от настройки.
6. Иметь возможность настраивать бота: изменять и добавлять темы, источники, время рассылки.
7. Чтобы новости не повторялись и объём дайджеста оставался небольшим.

## 3. MVP (минимальный набор функций для первой версии)

- Фиксированный список тем задаётся в конфиге (без интерфейса управления через бота).
- Для каждой темы в конфиге также фиксируется уровень детализации/глубины анализа.
- Ограниченный, заранее определённый набор источников новостей.
- Рассылка дайджеста 1 раз в день по расписанию.
- Без персонализации под разных пользователей — бот шлёт дайджест только мне (single-user режим).

## 4. Вне рамок MVP (backlog на будущее)

- Шаблон первичного опроса пользователя для формирования тем и источников (онбординг-диалог в самом боте).
- Поддержка нескольких источников на тему одновременно.
- Дедупликация новостей.
- ML-классификация тем (автоматическое определение, к какой теме относится новость).
- Мультипользовательский режим.
- Веб-панель настроек.
- Парсинг сайтов, у которых нет RSS/API.

## 5. Источники новостей

- RSS-ленты интересующих сайтов.
- News API (например, NewsAPI.org или аналог).

**Примечание (после ревью):** News API отдаёт только заголовки и краткие сниппеты новостей, без выдержек из первоисточника. Для темы "Налогообложение РФ" с уровнем глубины `summary` (раздел 8) это может быть недостаточно — там требуются выдержки из закона и ссылки на первоисточники. Скорее всего для этой темы понадобится RSS официальных/профильных источников, а не общий агрегатор. Конкретный выбор — см. раздел 11 (открытые вопросы), решается на Этапе 2.

## 6. Нефункциональные требования

- **Пользователи:** 1 (я) в MVP — бот отправляет дайджест только вам. Структура базы данных при этом спроектирована с заделом на многопользовательский режим (см. ARCHITECTURE.md, раздел 4), чтобы не переписывать её с нуля при масштабировании — само масштабирование остаётся за рамками MVP (раздел 4).
- **Хостинг:** VPS (решено на Этапе 1.5, после сравнения с вариантом "старый ноутбук как домашний сервер" — приоритет отдан минимуму возни и стабильности). Провайдер: **FirstVDS**, тариф **VDS Старт** (1 CPU, 2 ГБ RAM, 40 ГБ SSD), локация — **Амстердам** (решено на Этапе 5). Локация в Нидерландах выбрана вместо Москвы: Anthropic API проверяет географию IP-адреса при каждом запросе, а Россия не входит в список поддерживаемых регионов — сервер с российским IP не смог бы стабильно обращаться к Anthropic API даже с оплаченным балансом. Компромисс: администрирование сервера (SSH) из России может периодически быть затруднено — по данным самого FirstVDS, IP-адреса в Амстердаме/Алматы иногда попадают под фильтрацию российских операторов как подозрительные (VPN/прокси).

## 7. Роль ИИ в пайплайне

**Важное ограничение (зафиксировано после ревью на Этапе 1.5):** ИИ работает **только** над статьями, которые уже собраны из настроенных источников (RSS/News API). ИИ **не выполняет самостоятельный поиск** в интернете и не обращается к внешним источникам напрямую — вся "сырая" информация поступает в него только через модуль сбора новостей (`news_fetcher.py`). Это ключевое решение для MVP: оно исключает необходимость в веб-поиске силами ИИ, ограничивает стоимость обращений к LLM API (обрабатывается только уже отфильтрованный по источникам объём текста) и упрощает архитектуру.

ИИ используется на нескольких этапах обработки уже собранных статей:

1. **Фильтрация / ранжирование релевантности** — из статей, полученных из источников по теме, ИИ отбирает те, что действительно относятся к теме и достаточно значимы, чтобы попасть в дайджест.
2. **Анализ нескольких источников** — если по одной теме есть материалы из разных источников (в рамках MVP — обычно один источник на тему, см. раздел 4), ИИ сопоставляет их между собой (устраняет дубли по смыслу, дополняет одну новость деталями из другой).
3. **Агрегация ответа по темам** — итоговый дайджест формируется по темам: под каждой темой — свой блок с относящимися к ней новостями.
4. **Декомпозиция тем в зависимости от глубины** — ИИ формирует текст по теме в формате, соответствующем её уровню глубины (см. раздел 8), используя только текст уже собранных статей.
5. **Перевод на русский язык** — источники по некоторым темам (например, зарубежные издания о K-pop) могут быть на английском или другом языке. Независимо от языка исходной статьи, итоговый текст дайджеста всегда формируется на русском языке. Перевод выполняется той же моделью в рамках того же запроса, что и фильтрация/форматирование — отдельный шаг или модуль для этого не требуется.

## 8. Уровни глубины темы

**Уточнение (после проектирования архитектуры, Этап 2):** глубина — это свойство не самой темы, а связи "пользователь + тема" (в терминах БД — таблица `user_topics`, см. ARCHITECTURE.md). Это сделано, чтобы одна и та же тема (например, "Видеоигры") могла в будущем отслеживаться разными пользователями с разной глубиной. Для текущего MVP (1 пользователь) на практике это не меняет поведения — просто корректная модель данных на будущее.

Для каждой связки пользователь+тема задаётся один из двух уровней:

| Уровень | Описание |
|---|---|
| `summary` | Подробная выжимка: ключевые детали, выдержки из первоисточника (закона, официального заявления и т.п.), пояснения, ссылки на источники. |
| `briefly` | Максимально сжато: суть новости в одну строку, без деталей и подробностей. |
